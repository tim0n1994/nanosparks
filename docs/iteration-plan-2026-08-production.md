## 1. 调研结论（2026-07 两轮调研，含 v4 定点验证）

### 1.1 竞品格局（详表见 git 历史 v3；结论不变）

中文市场"贴链接→带说话人全文→深度加工→图文分发→社交沉淀"闭环无人做。Podwise/Snipd/通义听悟/听脑AI 全部停在工具层。我们的证据链体系（每句话回放到说话人+时间戳）是现成的差异化武器。

### 1.2 v4 定点验证结果（修正 v3 三处断言）

1. **SenseVoice 词级时间戳有坑**：SenseVoiceSmall 的词级时间戳是 2024/11 补的 CTC 对齐，存在"时间戳数量与字符数不匹配"的已知 issue；说话人分离不是模型原生输出，需 FunASR 自托管管线（fsmn-vad + CAM++ 组合）。走硅基流动 API 拿不到可靠词级时间戳 → v3 "接口契约直接实现"的说法过于乐观。
2. **阿里百炼（Model Studio）录音文件识别是中文一体化最优解**：paraformer-v2 / fun-asr 异步文件转写，**原生输出词级时间戳（words[begin_time,end_time]）+ speaker_id（diarization_enabled）+ 敏感词过滤 + 热词定制**，单文件 ≤12h/2GB，语音时长计费（静音不计费），支持 zh/en/ja/yue/ko/de/fr/ru。限制：开分离建议音频 ≤2h（超长需切片）；输入必须是公网 URL。
3. **《人工智能生成合成内容标识办法》2025-09-01 已施行**：作为生成服务提供者，我们有义务①生成内容加显式标识；②提供下载/导出时在文件元数据写隐式标识（服务商编码+内容编号）；③用户协议写明标识规范。小红书/微信/抖音已上线"主动声明"入口，未声明被平台检测将强制打标（影响流量），恶意删改标识可封号。**直接约束 B 阶段图文包的导出与发布引导。**

### 1.3 平台发布通道 & 1.4 版权红线

结论不变（v3）：做"内容包生成器"不做"自动发布机"；公众号 API 是唯一官方直连通道（仅企业认证号）；小红书无笔记发布 API、RPA 有封号风险；版权分层——私有转写低风险、公开页仅摘要+短引用带出处、主播认领化敌为友。

### 2.3 两个生死体验时刻

**第一分钟**（决定激活）：贴链接 → 秒级返回元数据卡（封面/标题/时长/预计完成时间）→ SSE 阶段文案（下载中→转写中→整理说话人→生成导读）→ **转写完成即先开放全文阅读**（导读/金句异步补上，骨架屏占位）。禁止白屏等待全管线。

**等待黑洞**（决定回访）：>5 分钟的处理必须有离开页面的自由——完成后站内红点+邮件通知（B 阶段加服务号模板消息）。付费用户队列优先。

## 3. 北极星与原则

**北极星**：任何播客链接 → 10 分钟内变成一篇可读、可信（说话人+时间戳）、可再创作的图文内容。

原则（v3 五条保留，改一条）：
1. 读优先于研；2. 管线不推倒重来；3. 发布 human-in-the-loop；
4. **每集首转成本 <¥1.5、缓存命中 ≈¥0**（见 §7）；
5. 公开内容合规分层（§8）。

## 4. Phase A — "读播客"核心 + 生产上线（第 1–4 周）★ 主线

### A0 工程前置（0.5 天）

- 提交当前未跟踪/修改文件；`docs/` 规划文档入库。
- ingest route 的 mode 参数与新 resolver 链对齐（robot/creator/ugc 语义复核）。

### A1 万能链接接入 + 全局转写缓存

**resolver 链**（每源一个小模块，对齐 `xiaoyuzhou/parser.ts` 模式）：

| 源 | 路径 | 已知深坑与对策 |
|----|------|---------------|
| 小宇宙 | 已有 client | 频控：请求限速+UA 伪装；海外 IP 可能风控（见 A4 部署） |
| YouTube | 已有 yt-dlp | 年龄/地区限制 → cookies 配置项；>4h 提示分段 |
| Apple Podcasts | URL 提取 id → iTunes Lookup API（`/lookup?id=`）→ feedUrl → RSS → 按 `?i=` episodeId 或标题+时长匹配单集 | Lookup 免费无需 key；RSS enclosure 才是真音频 |
| Spotify | **不提供音频**（独占内容拿不到） | oEmbed 拿节目名 → iTunes Search 找同名 RSS → 让用户确认是否同一节目；找不到明确告知"Spotify 独占无法获取，试试其他平台链接" |
| 通用 RSS | feed 解析（节目=最近 N 集列表让用户选，单集=直转） | 跟随 chartable/podtrac 等跳转前缀；部分 CDN 校验 UA/Referer |
| B站 | yt-dlp（内置支持） | 部分内容需登录 cookies；充电专属/番剧不可取 → 人话报错 |
| 音频直链 | content-type 探测 + ffprobe 验证 | 大小/时长上限熔断 |
| 兜底 | yt-dlp 万能提取（1000+ 站点） | 失败错误分类：需登录/地区限制/无音频 |
| 上传 | 已有 upload 模块接入同一 Flow | — |

**全局转写缓存（v4 新增，核心设计决策）**：

- `episodeKey` = `platform:platformId`（无平台 ID 的用音频 content-hash 兜底）。
- ingest 前查缓存：命中 → 用户 Corpus 直接引用已有 Conversation（转写/导读/金句共享层），跳过整条管线，秒级"处理完成"。
- 私有层（高亮、笔记、Brief、图文包）按用户隔离；共享层只读。
- 收益：a) 成本从 ¥1+ → ≈0；b) 热门集秒开 = 体验碾压竞品；c) "N 人读过"聚合 → C 阶段社交信号与高光密度的地基；d) 免费额度设计的前提（§7）。
- 对应 schema：`GlobalEpisode(episodeKey unique, conversationId, readCount, firstIngestedAt)`；隐私边界：仅公开来源内容进缓存，上传文件永远私有。

### A2 ASR + 说话人分离架构（v4 修正）

**三条路线对比**：

| 路线 | 组成 | 词级时间戳 | 说话人分离 | 1.5h 成本 | 运维 |
|------|------|-----------|-----------|----------|------|
| **R1 阿里百炼一体化**（中文默认）★ | paraformer-v2/fun-asr，`diarization_enabled` | ✅ 原生 words[] | ✅ 原生 speaker_id | ~¥0.5–0.9（语音时长计费，待实测核价） | 零运维、无 GPU |
| R2 Deepgram（英文默认） | 已有 adapter，开 diarize 参数 | ✅ | ✅ 内置 | ~$0.3–0.4 | 零运维、无 GPU |
| R3 本地 whisper + pyannote（隐私/降本路线） | I2 已建成 | ✅ | ✅ community-1 | GPU 摊销 | 需 GPU worker |

- **中文默认 R1**：新增一个 `ParaformerProvider`（异步任务：提交→轮询/回调→下载 JSON），输出直接是带 speaker_id 的句子+词级时间戳 → `normalize_turns` 输入格式几乎现成。注意：①输入必须公网 URL——音频先落 MinIO 出预签名 URL；②开分离建议 ≤2h，超长用现有 chunker 切片分段提交再拼接（speaker 标签跨片对齐：用重叠窗口声纹或 LLM 说话人映射兜底）；③热词 API 挂节目级术语词典（解痛点 #5）。
- **英文默认 R2**：Deepgram adapter 已存在，只需开启 diarize；AssemblyAI（$0.17/h 含分离）做备选。
- **R3 转为隐私/本地路线**：pyannote 管线不删，模型路由（I3 已有 sensitive→local）指向它；生产初期不部署 GPU。
- **LLM 后处理 pass**（新增小步骤，进 extract 前）：术语词典纠错+口癖清理（"然后/那个"密度压缩，Turn.cleanText 已有此语义）+ 中英夹杂格式规范。DeepSeek 级模型，成本 ~¥0.1/集。
- 语言路由：小宇宙/B站/中文标题 → R1；其他 → 探测首 60s 语种再路由；Setting 可覆盖。
- 退出标准：中文 fixture WER/DER 对比现状出数；1.5h 集 ≤8 分钟出稿；成本打点进 ExtractionRun.costUsd。

**⇒ 架构红利：Phase A 上线完全不需要 GPU，一台 CPU VPS 即可。**

### A3 阅读器（产品生死线）

**信息架构（`/read/[conversationId]`，自上而下）**：

1. Hero：封面/节目名/主播/时长/原链接（版权姿态：显著回链）/处理状态。
2. TL;DR 卡：一句话总结 + 3–5 要点（决定"值不值得读"，解 P1 首要 JTBD）。
3. 章节导航（sticky，点击滚动定位）。
4. 金句墙：3–5 张（extract 已产出 quote 类 ThoughtUnit），每张预留"生成卡片"按钮位（B 阶段点亮）。
5. 正文：Turn 聚合成段，说话人色条+名字缩写头像；段落时间戳 chip 点击 seek 内嵌播放器；金句内联高亮。
6. 底部：图谱/Ask 入口（研究功能降级为高级入口）、导出 MD/Obsidian（context-pack 已有，加按钮）。

**关键细节**：

- **性能**：2h 集 ≈ 600–1000 Turn。首屏 SSR 首章节 + 按章节懒加载/虚拟滚动；已完成会话页用 Next 16 `use cache` 长缓存。
- **双语对照（v4 新增）**：英文集"翻译本集"按钮 → 段落级翻译（DeepSeek，~¥0.3–0.6/集，按需触发计一次额度）→ 三种模式：原文/译文/对照。存 `Turn.translationJson`（语言→文本 map）。翻译结果进全局缓存共享层。
- **说话人改名**：点说话人名 inline 编辑（PATCH participant 接口 I2 已有）+ speaker-mapper 的 LLM 建议名预填。全文即时替换。
- **播放器**：播原始 enclosure/平台 URL（不公开转发我们的 MinIO 拷贝）；源失效时 fallback 到 MinIO 预签名 URL（仅登录所有者可见）。
- **阅读进度**：`ReadingProgress(userId, conversationId, turnIndex)`，回访续读提示——留存钩子。
- **提交页**：首页一个大输入框；SSE 阶段化进度（§2.3）；转写完成先读。
- 移动端优先：字号/行距设置、暗色、底部迷你播放器。

### A4 部署与护栏（v4 大幅具体化）

**国内 vs 海外拓扑决策**：

| 维度 | 海外（HK VPS，快路径）★A 阶段 | 国内（正路径，B/C 前置） |
|------|------------------------------|--------------------------|
| 备案 | 不需要 | ICP 备案 2–4 周（个人可备；经营性质后续需企业主体） |
| 国内访问 | HK 尚可 + Cloudflare | 最优 |
| Clerk 登录 | 可用（邮箱/Google/手机号） | Clerk CDN 国内不稳 → 届时换 next-auth（手机号+微信扫码）或自建代理 |
| 支付 | 不做（邀请制免费） | 微信/支付宝需企业主体；过渡可用爱发电 |
| 抓取小宇宙/B站 | 海外 IP 有风控概率 → 低频+重试+必要时国内代理出口 | 国内 IP 稳 |

**决策**：A 阶段 HK VPS + Clerk + **邀请制免费**（不碰支付、控成本、制造稀缺）；**备案与企业主体注册立即并行启动**（它们是 B/C 的最长前置路径）。

**护栏（具体数字）**：单集成本熔断 ¥3；单用户并发处理 1 集、日上限 5 集；音频 ≤4h；免费额度见 §7。Langfuse 成本仪表 + 队列 Prometheus（已有）。Postgres 每日备份 + MinIO 生命周期（retention 已有）。

**Phase A 退出标准**：10 条真实链接（小宇宙×3、YouTube×2、Apple Podcasts×2、RSS×1、B站×1、mp3 直链×1）全部 10 分钟内出带说话人全文；缓存命中秒开；手机阅读流畅；邀请注册可用；单集成本实测数据入库。

## 5. Phase B — 图文分发（第 5–8 周）

### B1 内容包生成器（`src/lib/publish/`）

**卡片渲染规格**：

- 尺寸 1242×1656（3:4）；模板 3 套：金句卡（大引号+说话人+节目出处+时间戳）、清单卡（3–5 要点）、对谈卡（双人气泡）。封面模板：大字标题+节目名+品牌角标。
- 技术：satori（React→SVG）+ resvg 转 PNG；中文字体思源黑体/霞鹜文楷（OFL 可商用）；emoji 用 twemoji SVG；字数→字号档位表自适应折行。
- **合规（《标识办法》第五条）**：导出 PNG 元数据写入 AIGC 隐式标识（XMP：属性信息+服务商编码+内容编号）；界面显著提示"AI 辅助生成"。

**文案生成规格**（每平台一个 prompt 文件，走结构化输出 + ExtractionRun 记账）：

| 平台 | 结构约束 | 硬规则 |
|------|---------|--------|
| 小红书 | 标题 ≤20 字含钩子（数字/悬念/身份代入）；正文 ≤1000 字：共鸣开头 2 行 → 要点 3–5 条 → 互动提问结尾；emoji 1–2/段；tags 5–8（垂类+泛流量混合） | 是解读不是搬运；出处行固定「🎙️来源：《节目名》EP.X」 |
| 公众号 | digest ≤120 字；小标题分节；金句用引用块+说话人；文末"阅读全文文字版"链接（content_source_url 指向 C1 公开页） | 全图走素材接口；HTML 内联样式白名单 |
| 知乎 | 文章版（导语+分节）+ **回答版**（结论先行+播客论据+出处） | 回答版蹭已有高热问题，冷启动强于发文章 |

- **敏感词过滤**：发布前本地词库扫描（医疗宣称/绝对化用语/引流词），命中高亮+改写建议——小红书限流主因，调研反复证实。
- **一鱼多吃矩阵**：1 集 → 公众号长文 ×1 + 小红书笔记 ×2–3（金句版/清单版/争议观点版，`PublishPackage.variant`）+ 知乎回答 ×1。

### B2 发布通道

- **公众号双通道**：a) 认证服务号 → API 直连（图片先传素材接口换 media_id；正文 <2 万字符；外链图会被过滤）→ `draft/add`，用户在公众平台点发布（或配置直接 `freepublish/submit`）；b) 无认证号（多数个人用户）→ 内联样式 HTML + 「复制到公众号」按钮（Clipboard API 写 `text/html` flavor，粘贴进编辑器保留样式）。
- **小红书/知乎：导出即发布**——图包下载 + 文案分段复制（标题/正文/tags 各一键）+ 二维码传图到手机。明确不做自动发布（封号风险写进产品文案）。
- **AI 标识引导**：发布指引内置各平台声明路径（小红书：设置→内容类型声明→勾选"笔记含 AI 合成内容"），说明不声明被强制打标/限流的风险。
- 发布记录：`PublishPackage.status`（draft/exported/published）+ 用户回填链接；AuditLog。

**退出标准**：一集 → 一次点击 → 三平台产物齐全；小红书实发 5 篇验证真机显示与流量表现；公众号 API 通道在认证号上跑通。

## 6. Phase C — 内容社交（第 9–14 周，逐层解锁）

### C1 公开内容库（地基 + 获客引擎）

- `/p/[slug]`：导读+章节+金句（≤10 条短引用+出处回链），**全文需登录**（合规分层）。
- SEO：目标词「{节目名} 文字版/文稿」「{嘉宾名} 播客」；h1={集标题}+文字版；schema.org PodcastEpisode；OG 图复用卡片渲染器；sitemap + 百度站长主动推送 + Google；微信搜一搜靠公众号长文承接（B 已产出）。
- **Dogfood 增长环（v4 新增）**：用自家 B1 给自家账号发内容——每处理一集热门播客即产出获客素材，「工具产出→内容矩阵→引流→新用户→更多缓存」正循环；同时是产品最有说服力的活 demo。

### C2 高亮与收藏（单人价值闭环）

划句高亮（落 Turn+offset，即现成 EvidenceSpan 结构）→ 高亮库 → 一键生成金句卡（复用 B1）；Collection 专题集（跨播客按话题收集）。

### C3 关注与 Digest（回访钩子）

关注节目（RSS 轮询新集自动转写进缓存）+ 关注话题；每周 digest：邮件 + 服务号模板消息（此时应有认证号）。

### C4 社区层（数据闸门：C1 周 UV>1k 或 C2 周高亮用户>100 才启动）

高亮即评论（对某句话的公开短评，带说话人+时间戳上下文，比小宇宙评论时间戳更精确）；话题小组=共享 Collection；**主播认领**：认领后获官方标识/全文公开权/读者数据/shownotes 工具（B1 顺手产出）——把版权对手变生态盟友，亦是潜在 B 端收入。

**定价（对标：Podwise $5.9/月 20 集、听脑AI ¥199/年）**：

- **所有数字上线后按 ExtractionRun.costUsd 实测月度校准。**

## 12. 决策记录（ADR，v4 增量以 ★ 标注）

| # | 决策 | 理由 |
|---|------|------|
| 1 | 产品重心转向"读播客"消费产品 | 市场验证充分；研究能力降级为高级功能 |
| 2 | ★中文 ASR+分离走阿里百炼一体化 API；pyannote 降为隐私/本地路线 | 原生词级时间戳+speaker_id 一次调用拿齐；SenseVoice API 路线时间戳不可靠；**Phase A 免 GPU 上线** |
| 3 | 分发=内容包生成器 + human-in-the-loop | 小红书无 API 且封号风险；公众号 API 唯一直连 |
| 4 | ★全局转写缓存 + 缓存命中不占免费额度 | 成本复利+热门集秒开+社交密度地基；Podwise corpus 同模式验证 |
| 5 | 公开页只放导读+短引用，全文登录可见 | 版权与 SEO 的平衡点 |
| 6 | 社区功能设数据闸门 | 冷启动失败率高，先验证单人价值留存 |
| 7 | ★A 阶段 HK VPS + Clerk + 邀请制免费；备案与企业主体立即并行 | 最快上线路径；备案/主体是 B/C 最长前置，不能串行等 |
| 8 | ★双语对照按需翻译（不默认全翻） | 强需求但有成本；按需触发计额度，译文进共享缓存 |
| 9 | ★导出写 AIGC 隐式标识+引导平台显式声明 | 《标识办法》强制义务；不合规=限流/封号风险转嫁给用户 |
