## Problem Statement

Conversations (podcasts, interviews, live streams, social threads) contain dense intellectual value, but listeners lack tools to extract, structure, and explore the ideas within them. Existing solutions offer flat summaries or raw transcripts. Users need a way to see HOW ideas connect, evolve, and conflict — a structural map of thinking, not just a recap of talking points.

## Demand Evidence

- Founder (JC) experiences this pain directly: consumes podcasts, interviews, and social content but struggles to retain and connect ideas across episodes
- Status quo: manual note-taking, scattered highlights, or generic AI summaries that miss the argumentative structure
- The 80/20 observation applies: 80% of listening time is spent on setup and tangents; 20% contains the actual intellectual payload

## Status Quo

Current workflow for a knowledge worker digesting a 90-minute podcast:
1. Listen at 1.5x speed, pausing to take notes
2. Export highlights from podcast app (if available)
3. Paste transcript into ChatGPT/Claude, ask for "key points"
4. Receive a flat bullet list that misses argument structure, counter-arguments, and intellectual lineage
5. Manually cross-reference with other episodes or sources
6. Ideas remain fragmented and disconnected

This takes 2-3 hours per episode and produces low-retention output. Most listeners skip deep engagement entirely.

## Target User & Narrowest Wedge

**Target user:** Knowledge worker who consumes 5+ hours of conversational content weekly (podcasts, interviews, live streams) and wants to extract lasting intellectual value without spending equal time note-taking.

**Narrowest wedge:** YouTube podcast channel analyzer — paste a channel URL, the system auto-selects recent episodes, transcribes, deconstructs argument structure, and renders an interactive idea map. Users can browse by topic, speaker, or argument thread.

## Constraints

- Must handle unstructured, messy conversational data (interruptions, digressions, off-topic segments)
- Must preserve speaker attribution and argumentative structure (who said what, who disagreed, who refined whose point)
- Must generate reference links that are actually useful (not generic SEO spam)
- Must render visually — text-only output fails the "structural map" promise
- Must be fast enough that users prefer this over listening at 2x speed

## Premises

1. **The user is a podcast listener who wants to save time AND get inspired — not just skim, but deeply understand the ideas.** — AGREED
2. **The output is a visual, interactive map of ideas (not text summary) with reference links.** — AGREED
3. **The moat is the prompt engineering + visualization design, not the LLM itself.** — AGREED

## Approaches Considered

### Approach A: The Manual Curator (Validation Path)
Manually generate 10 visual deconstructions of popular podcast episodes. Publish as a newsletter or Twitter thread. Measure engagement (shares, replies, "I want this for my favorite show" requests).

- **Effort:** Small (1 week)
- **Risk:** Low
- **Pros:** Validates demand before building, produces marketing content, refines prompt design
- **Cons:** Not scalable, no product yet, relies on founder's taste

### Approach B: The Channel Analyzer (RECOMMENDED — USER SELECTED)
A web platform that ingests conversational content from YouTube podcast channels (auto-transcribe via Whisper, structure via prompt pipeline, visualize via interactive graph). Three content ingestion modes:
- **Robot mode:** Auto-follow channel uploads, process new episodes within 1 hour
- **Creator mode:** Channel owner submits episode URLs for priority processing
- **UGC mode:** Users create custom "playlists" of episodes across channels, generating cross-episode idea maps

Output: interactive visualization showing argument threads, speaker positions, key quotes, and AI-generated reference links.

- **Effort:** Medium (4-6 weeks for MVP)
- **Risk:** Medium
- **Pros:** Automated at scale, network effects from UGC playlists, clear value prop for both listeners and creators
- **Cons:** YouTube API dependency, transcription costs, content moderation for auto-ingested material

### Approach C: The Universal Conversation Layer (Vision)
Multi-source aggregation: video platforms (YouTube, Bilibili), audio platforms (Spotify, Apple Podcasts), social (X threads, Reddit AMAs), real-time (Discord, Clubhouse). Universal conversation ingestion with source-agnostic analysis pipeline.

- **Effort:** Large (3-4 months)
- **Risk:** High
- **Pros:** Defensible moat, platform play, captures all conversational content
- **Cons:** Fragmented APIs, varying data quality, massive scope, hard to get right

## Recommended Approach

**Approach B: The Channel Analyzer**

Rationale: Validates the core value proposition (structural idea extraction + visualization) with a single, high-quality content source (YouTube podcast channels). The three ingestion modes (robot/creator/UGC) create multiple growth loops. YouTube provides free transcription via Whisper API, established channels provide steady content flow, and UGC playlists create organic discovery.

## Open Questions

1. Which visualization format works best? (Argument map, timeline, topic cluster graph, or hybrid?)
2. How to handle multi-episode threads? (Same guest across episodes, recurring topics, evolving positions)
3. What's the reference link generation strategy? (RAG against Wikipedia/arxiv, web search, or curated knowledge base?)
4. Monetization: freemium (free for public channels, paid for private/custom sources) or creator revenue share?
5. Content moderation: how to handle politically sensitive or misinformation-heavy conversations?

## Success Criteria

- [ ] Auto-process a new YouTube podcast episode end-to-end in < 10 minutes
- [ ] Visual output renders in < 3 seconds on mobile
- [ ] Reference links have > 70% relevance score (human-rated)
- [ ] 100 active users within 4 weeks of launch
- [ ] 3 UGC playlists created organically within 2 weeks

## Distribution Plan

- **Channel:** Product Hunt, Hacker News, podcast creator communities (Reddit r/podcasting, Discord servers)
- **Growth loop:** Creators embed visualizations on their sites → listeners discover platform → listeners create UGC playlists → more creators want their content visualized
- **Pricing:** Free for public channel analysis + 3 UGC playlists; $9/mo for unlimited playlists + private source ingestion + API access

## Dependencies

- YouTube Data API v3 (channel listing, video metadata)
- Whisper API or local Whisper instance (transcription)
- LLM API (Claude/ChatGPT for structured extraction)
- Vector database (Pinecone/Weaviate for reference link RAG)
- Frontend framework (Next.js + D3.js or Cytoscape.js for visualization)
- Database (PostgreSQL for relational data, Redis for job queues)
- Hosting (Vercel frontend, Railway/Render backend)
